## 目标与依据

本规范定义自动化的输入、权限、结果和失败边界。操作、认领/交接格式、需求及验收规则唯一依据为 [GIT_WORKFLOW](../docs/GIT_WORKFLOW.md)。任务来自 GitHub Issues，Project 为投影视图，不维护本地状态镜像。

## 事件与结果

| 输入 | 结果 |
| --- | --- |
| dev 管理脚本/工作流变化、手动初始化 | 幂等准备标签、阶段里程碑、原生父子/依赖关系与 Project |
| Issue 元数据/状态、认领、验收或 PR 状态/审查变化 | 回读当前任务并全量核对依赖、阶段与看板 |
| 普通讨论评论 | 不执行完整同步；候选事件在配置 Node 环境与 API 调用前精确过滤；编辑/删除旧操作时仍核对 |
| 每六小时或普通手动运行 | 全量补偿漏事件/临时失败；无变化不重复写入 |
| 指定 PR/head/范围的手动审查记录 | 核验真实发起者、有效认领、前置、任务引用与当前 head，生成审查和 collaboration 状态，不等待 Project 全量同步 |
| 指定任务/交付 SHA/证据的验收准备 | 生成可读准备评论及确认文本，记录交付版本；不批准、不关闭 |
| 授权者引用准备记录的确认评论 | 核验身份、类型、版本、范围及重开时间，自动回填验收记录 |
| 授权者直接 Close as completed | 绑定关闭事件快照与关闭前准备记录，归档确认人/版本/范围/证据并同步 Project；无需验收评论 |

## 权限与数据

管理工作流使用源码读取、Issues 写入、PR 读取及提交状态写入权限。个人 Project 使用独立 PROJECT_TOKEN；PROJECT_NUMBER 可指定已有项目，否则精确匹配 Riverlight 开发，仅初始化可创建。令牌不进入源码、输出或任务正文。

阶段规格来自 DEVELOPMENT_PLAN，优先级、阶段、任务编号、依赖及状态由 Issue 明确字段解析。未知/循环依赖、未分诊字段、状态冲突进入分诊；重复任务编号明确失败。原生关系只协调本项目任务，保留外部引用。

默认分支保留管理事件入口，Issue/评论/PR/定时事件执行受保护 dev 中已审查的管理脚本，不执行贡献者 PR head。手动运行使用所选 ref，选择 main 时仍执行 dev 的管理实现。默认分支的入口和 dev 的实现分别集成，不要求将应用源码发布到 main；真实事件成功后才确认启用。

认领和 Project 写入按仓库串行；先写可恢复 bot 回执，再投影负责人。中断和超时不释放认领；共用账号执行者代号不作为独立身份认证。工作流核验审查记录，不替代实际代码审查。验收算法兼容旧摘要，新摘要排除执行进度与证据，未知需求章节仍参与；视觉确认依据用户明确认可。

## 执行与失败边界

- 常规同步最多 20 分钟，分页读取；执行时回读现状，不依赖事件严格顺序。一轮复用评论、阶段关系、权限与必要审查读取；写入使关联缓存失效，不跨运行缓存。
- 管理测试仅在本地按需运行，GitHub Actions 的 check、认领、同步、验收准备与审查记录均不运行自动测试。运行时保留身份、输入、认领冲突、版本与并发变化校验。工作流粗筛候选评论，脚本共用过滤器核对当前正文和编辑前正文；无关编辑可能启动 runner，但跳过环境配置与管理写入。
- 审查确认仅读取所需任务/PR/认领及依赖；结果立即写入 Actions 状态，Project 在下一次同步投影。
- 已有 Project 的字段/选项不兼容时失败，不清空已填数据；多个同名项目要求指定编号。维护内置视图，保留自定义视图。
- 身份、版本、范围或认领冲突不放行；验收记录更新前核对正文未并发变化。旧交接绑定原认领编号，不能释放继任者。
- 首次关闭验收只使用真实 closed 事件中的 Issue 快照；与当前版本/范围不同则拒绝。关闭原因须 completed、关闭者须为授权且有写权限的用户，时间线不得带自动关闭提交。关闭前须已有同版本/范围的 bot 准备记录且任务处于待验收。Bot、PR 自动关闭、取消/重复关闭不生成验收。
- 关闭回执先持久化再更新正文，重复事件幂等。重开或版本/需求变化使确认失效；旧关闭事件不能批准新交付。补偿运行只恢复已有关闭回执。首次记录失败可重跑原关闭运行；缺关闭前准备时，可补准备后由授权者引用该记录新发确认评论，或重开后重新验收。新评论只确认当前版本，不补造历史快照；其时间必须晚于准备记录及最近重开事件。
- API/授权失败明确报告，凭据及未过滤响应不打印。GET 429/502/503/504 总计最多三次尝试，延迟有上限；写操作不盲目重放，响应丢失由后续回读恢复。
- 分支保护单独授权，要求所选 main/dev 专属规则集及预期更新时间，回读结果；新建 dev 要求 absent 预期且无重叠。权限/套餐不足明确失败。
- 发布、代码审查、产品验收分别记录；管理自动化不关闭任务/里程碑、不合并 PR。

## 验收

检查幂等初始化、任务关系、状态与重开、认领竞争/交接、版本与范围失效、确认身份和看板投影；测试缓存失效、无关事件过滤、审查独立路径与旧记录兼容。真实 GitHub 行为另核验，不能用模拟测试替代启用证据。

实现入口为管理工作流、github-management、github-collaboration、workflow-command 与 github-settings；检查范围由 ci-policy 与站点工作流选择。逐次结果及启用操作留在 Actions/聊天。
