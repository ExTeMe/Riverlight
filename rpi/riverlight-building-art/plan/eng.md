# 试放证据、模型契约与回归

## 固定场地探针

把 `createScene('T04-WEST').city` 装进一个启用西岸试验能力的内存城市。用既有 `City.paint` 在格坐标 `x=-18…-8, z=-1` 补齐街面小径，再铺 `(-12,-2)` 与 `(-11,-2)`。试放参数如下，所有位置和大小单位为米。

| 地块 | 中心 X/Z | 宽 × 深 | 代理入口 XYZ |
| --- | --- | --- | --- |
| 住宅 | `(-64.75, -12.25)` | 9.5 × 12 | `(-64.75, 0.14, -7.90)` |
| 市集 | `(-49.50, -16.00)` | 14.5 × 11.5 | `(-49.50, 0.14, -11.65)` |

调用 `City.editParcel`，分别用现有 `cottage`、`market` 作临时代理，地块与建筑角度、建筑偏移均为零。两个地块成功，内侧边界 X 分别为 −60 与 −56.75，通巷间隔 3.25 米。市集地块东侧及南侧与已有铺装各留 0.25 米，正式入口需要接过这段边界。地块尺寸用于取景与首轮空间组织，模型可以按平剖面所需调整并复试。

用 `City.editPlatform` 试放位置 `(-12.75,14)`、宽深 5.5 × 4 米、坡长 2 米、升高 0.14 米的西岸方案。保留默认净宽 2.2 米及朝向。用 `buildWalkNetwork` 检查两处入口到过街北端，再查南端到西岸和平台，每段跳过图中其他过街。指定过街连接 `(-30.2,0.12,−1.9)` 与 `(-30.2,0.12,1.9)`。桥结构相同，现有岸道数仍为 218。试放只检查场地、代理入口和通行。实际建筑的占地和已制作锚点接入后必须复查。 [场地与路网](../../../src/riverfront-study.js) · [步行图](../../../src/walk-network.js) · [西岸复核](../../riverlight-development-review/implement/IMPLEMENT.md)

## 制作、加载与保存

| 部位 | 计划与接口 |
| --- | --- |
| Blender 交付 | 为住宅和市集各保存可编辑的 BLEND、近 GLB 和远 GLB。把建筑围护、室内、屋面、场地及可选可动件组织为可独立修改的对象集合。原文件、牵涉旧城的资产 ID 和工作区里的石居修改保持可恢复。两级共享米制原点、地面、朝向和主要轮廓。沿用 Blender 正面 −Y、导出后 Three.js 正面 +Z 的契约。 [模型契约](../../../docs/ASSETS.md#art-02-模型契约) |
| 资源接入 | 在独立开发场景加载明确的两套近远资源，并记录成功的具体级别、尺寸、材质和 ID。两栋使用独立稳定 ID。复用 `registerArchitectureAsset` 的材质及动画登记，核对旧目录宽深比的缩放在新样板为 1。优先沿用当前占地表示。若实际轮廓超出现有能力，先用能保住步道与相邻地块的真实外包范围验证，再决定是否扩展共享几何。 [加载入口](../../../src/asset-loader.js) · [模板注册](../../../src/models.js) · [占地](../../../src/parcel.js) |
| 锚点和净空 | 每栋提供一个供街道图使用的正式入口。在场所设计中独立表达市集后勤；首批公共入口节点沿用现有能力。给有实际遮蔽的部位提供同名同坐标的近远锚点，避免 Blender 自动添加后缀。登记覆盖模型、远景和活动构件的净空上界，渲染前也能读取。用浏览器资源快照与静态数据双向核对。 [研究发现](../research/RESEARCH.md#工程可行性与前提) · [净空](../../../src/elevated-roads.js) |
| 材质和灯位 | 嵌入可搬运纹理，保留基础色、光泽、法线与金属度，明确窗内发光和局部照明。比较样板需要的住宅局部灯和市集营业区灯。若现有按建筑类型挑灯位的限制导致实际问题，在点光预算内增加候选所需的按资产灯位数据，复用已有日期、天气和衰减；以入夜和重载复测。 [环境](../../../src/environment.js) |
| 存档与隔离 | 在派生场景使用独立名字和存储空间。试验资源从开发场景进入。沿用米制地块与历史版本转换，保留已发布 ID 的含义。若需要兼容西岸平台，继续使用其已验证的隔离机制。批次文件可导出并回读，未知试验记录给出反馈并保护原档。 [场景入口](../../../src/main.js) · [保存](../../../src/save-session.js) |

## 验证次序

1. **媒体可用。** 检查 BLEND 能单独打开，近远 GLB 均有有效网格及材料。浏览器实际注册两套资源，检查两级锚点，记录相同镜头下的近远文件大小、面数、材质批次和切换表现。历史无纹理预算作为对照，报告实测成本。
2. **放置完整。** 原角度和一个任意角度核对真实占地、入口与屋檐。试放先房后桥和先桥后房，检查净空不足在两条路径都被拒绝。确认门前不跨车道，路径按预期过街，岸道与航线仍有效。
3. **数据可靠。** 使用测试副本验证撤销重做、重载、导出回读和失败恢复。复跑 `baseline`、`parcel`、`riverfront`、`road-network`、`river`、`storage` 和 `autosave` 的定向测试。浏览器保留放置、转动、近远切换和回读证据。
4. **可正式集成。** 检查目前因 `cottage.glb` 等历史文件缺失而失败的产物入口，按最终资产清单与旧城行为验证后再决定生产启用。新样板的视觉确认和产物检查各自记录。 [发布检查](../../../scripts/check-dist.mjs) · [R1 模型契约](https://github.com/ExTeMe/Riverlight/issues/15)
