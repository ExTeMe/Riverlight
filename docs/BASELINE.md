# BASE-02：隔离测试基线

## 动态缺陷过程采集

观察记录在启动与每个采样阶段写入 `observations.json`，包含当前阶段、完成状态及页面提供的版本/浏览器信息。截图、后续操作或资源快照下载失败时保留此前样本，记录失败原因并保持测试失败；进程被强制终止时只能保留最后一次已写入的记录，`running` 不代表成功。录像和部分截图仍须结合实际操作判读。

执行 `npx playwright test --config playwright.evidence.config.js`，独立浏览器依次记录 T02～T05 的真实动画循环、近景截图、视频、操作轨迹及资源快照。结果在 `test-results/dynamic-evidence/`，不提交到源码。端口默认 5198，可用环境变量 `RIVERLIGHT_EVIDENCE_PORT` 指定空闲端口；不复用未知服务。

T04 连续观察 120 秒，覆盖原型船的名义航行周期；T05 记录初始、雨夜、停雨白天各阶段。录像需逐段人工判读，运行通过仅表示页面无捕获异常，不证明无穿模、正确通行或画面达标。模拟仍使用原型随机状态；真实墙钟观察时间不保证低帧率下的模拟推进时间。道路拆改、遮蔽和最大船型仍需专门操作。该入口使用全新浏览器上下文及场景独立存档，不操作用户原城。

## T01～T07 场景实验室

应用顶部的「探索场景」可打开七个可编辑场景；开发服务和构建后的站点均支持 `?scene=T06` 等入口。正常城市先保存，场景使用各自独立的数据库 `riverlight-scenes-<ID>-<density>`，返回时重新读取正常城市。保存失败时留在原页面并提示，不继续切换。每个场景初次进入恢复固定布局；「保存并重载」添加 `resume=1` 恢复该场景的编辑与镜头。「重置场景」先事务备份，再完整重载，清除天气过渡与动画时钟。

场景版本均为 1，布局标识种子 `20261103`，初始夏季晴天、17:30、风力 0.4、暂停昼夜、高画质。布局、近中远镜头、操作和未实现项由 `src/baseline.js` 定义；布局不使用随机数，车、人、天气动画仍为原型随机状态，不宣称确定性模拟。普通加载不改变用户城市格式，仍为 v2。

| --- | --- | --- |

T07 的 `density=sparse/standard/dense` 分别隔离存档。每个场景的「观察与记录」明确显示待实现项，不能把场景加载成功视作其未来系统验收。无效场景或密度显示启动错误，不打开或覆盖正常存档。

「导出资源快照」记录完整提交、工作区是否有未提交改动、场景版本/种子/密度、浏览器、视口、像素比、画质、环境、镜头、物件、实际车船人数、显示分区、最近一帧 draw calls/三角形和 WebGL 几何/纹理数量。资源数量不是内存字节；帧时间与 GPU 内存为 null，设备类别待登记。动态证据应另附操作过程、持续时间、前后截图；单张截图或单帧计数不证明长期性能或交通正确性。

回归入口：`tests/baseline.test.js` 检查七种布局、密度、合法占地、确定性和 v2 往返；`tests/e2e/scenes.spec.js` 在真实 Chromium 中覆盖七个入口、原城保护、天气、镜头、快照、重置和续存。

## 固定输入

场景 ID 为 `BASE-02`，场景版本为 1，布局标识种子为 `20261013`。城市布局使用明确放置列表，种子是追溯标识，不代表现有车、人和天气动画已经采用确定性随机源。

- 当前格式：`tests/fixtures/base-02-v2.json`，77 个物件、4 座建筑，半格小屋、旋转别墅、商业、公园、主路与桥、断开的道路及步道。
- 旧格式原件：`tests/fixtures/base-02-v1.json`，2 个物件，保留 v1 的旧水系与原始占地。迁移不能修改此文件或覆盖数据库中唯一原件。
- 镜头：位置 `[120, 115, 150]`，观察点 `[0, 0, 0]`；夏季晴天、16:30、暂停昼夜、风力 0.4、高画质。
- 布局与镜头定义：`src/baseline.js`；修改布局须提升场景版本并重新生成当前格式 fixture。旧格式原件用于兼容回归，不随新功能随意替换。

## 加载、隔离与重置

启动开发服务后，在其地址后加 `?baseline=BASE-02`。此入口只在开发模式启用，使用独立的 `riverlight-baselines` 数据库；正常城市仍使用原数据库。

进入时总是加载固定布局和镜头，不读取正常城市自动存档。测试修改可在隔离数据库保存或导出；重新进入入口会恢复初始布局。「我的城市 → 重新载入基线」会先备份当前测试城市，再重新加载固定入口，恢复初始布局、环境与镜头并清除上次天气的湿润度、云量和动画时钟。正常产品入口不显示基线按钮。

刷新恢复使用 `?baseline=BASE-02&resume=1`：此入口仍使用隔离数据库，读取已保存的测试城市、环境与镜头，刷新时继续恢复。没有隔离存档时使用固定基线；不能用正常城市做故障注入。镜头往返允许小于 `0.000001` 米的浮点误差，城市物件与占地仍须精确一致。

`tests/browser/storage.html` 是开发服务上的独立存档检查页面，每项创建专用测试数据库并清理自身数据，不使用正常城市数据库。自动检查可通过 `npm test` 执行。生成固定文件的入口为 `node scripts/generate-baseline.mjs`。

## 操作与判定

1. 连续两次进入基线入口，比较城市名称、77 个物件、固定时间、画质与镜头；临时车人状态不属于布局等价条件。
2. 选择小屋并移动，按 Esc 取消；原位置和数量保留。移动到水面或重叠位置应拒绝，原城市不变。
3. 拆除小屋后应有 76 个物件；撤销恢复到 77，重做再次为 76，再撤销恢复。
4. 保存为新存档，切换空白城市，再打开该存档；布局、环境和镜头恢复。切换备份可打开或导出原记录。
5. 导出城市后再导入，比较物件 ID、位置、占地、四向角度、道路、水系及环境；无效文件拒绝且保留当前城市。
6. 导入 v1 原件后应使用旧水系与原占地；导入事务保留原始 v1 数据、镜头及输入包装。数据库内原有 v1 记录首次覆盖前也归档原件。迁移、刷新和导出重入仍一致。
7. 启动读取失败时原自动存档不得被示范城覆盖；后续保存进入恢复存档。事务中止时新城市和备份一起回滚，重试可成功。

## 适用边界

BASE-02 是 R0 最小编辑、道路、水系和保存基线；上方 T01～T07 提供分系统场景骨架。任意角度、曲线道路、目的地、信号通行、撑伞及桥船净空仍按各系统任务验收。

资源与性能证据需注明提交、场景版本、浏览器、设备、分辨率、画质及实际活动量；未测项留空。现有 `getStats()` 的绘制统计不能代替完整帧 CPU/GPU 测量。
