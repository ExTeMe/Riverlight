# BASE-02：隔离测试基线

## 固定输入

场景 ID 为 `BASE-02`，场景版本为 1，布局标识种子为 `20261013`。城市布局使用明确放置列表，种子是追溯标识，不代表现有车、人和天气动画已经采用确定性随机源。

- 当前格式：`tests/fixtures/base-02-v2.json`，77 个物件、4 座建筑，半格小屋、旋转别墅、商业、公园、主路与桥、断开的道路及步道。
- 旧格式原件：`tests/fixtures/base-02-v1.json`，2 个物件，保留 v1 的旧水系与原始占地。迁移不能修改此文件或覆盖数据库中唯一原件。
- 镜头：位置 `[120, 115, 150]`，观察点 `[0, 0, 0]`；夏季晴天、16:30、暂停昼夜、风力 0.4、高画质。
- 布局与镜头定义：`src/baseline.js`；修改布局须提升场景版本并重新生成当前格式 fixture。旧格式原件用于兼容回归，不随新功能随意替换。

## 加载、隔离与重置

启动开发服务后，在其地址后加 `?baseline=BASE-02`。此入口只在开发模式启用，使用独立的 `riverlight-baselines` 数据库；正常城市仍使用原数据库。

进入时总是加载固定布局和镜头，不读取正常城市自动存档。测试修改可在隔离数据库保存或导出；重新进入入口会恢复初始布局。「我的城市 → 重新载入基线」会先备份当前测试城市，再恢复初始布局、环境与镜头。正常产品入口不显示基线按钮。

`tests/browser/storage.html` 是开发服务上的独立存档检查页面，每项创建专用测试数据库并清理自身数据，不使用正常城市数据库。自动检查可通过 `npm test` 执行。生成固定文件的入口为 `node scripts/generate-baseline.mjs`。

## 操作与判定

1. 连续两次进入基线入口，比较城市名称、77 个物件、固定时间、画质与镜头；临时车人状态不属于布局等价条件。
2. 选择小屋并移动，按 Esc 取消；原位置和数量保留。移动到水面或重叠位置应拒绝，原城市不变。
3. 拆除小屋后应有 76 个物件；撤销恢复到 77，重做再次为 76，再撤销恢复。
4. 保存为新存档，切换空白城市，再打开该存档；布局、环境和镜头恢复。切换备份可打开或导出原记录。
5. 导出城市后再导入，比较物件 ID、位置、占地、四向角度、道路、水系及环境；无效文件拒绝且保留当前城市。
6. 导入 v1 原件后应使用旧水系与原占地；首次覆盖保存前，数据库保留原始 v1 副本。迁移、刷新和导出重入仍一致。
7. 启动读取失败时原自动存档不得被示范城覆盖；后续保存进入恢复存档。事务中止时新城市和备份一起回滚，重试可成功。

## 适用边界

这是 R0 最小编辑、道路、水系和保存基线，后续 BASE-03/BASE-04 可引用这些固定输入；不代替完整 T01～T07 场景。任意角度、曲线道路、目的地、信号通行、撑伞及桥船净空仍按各系统任务验收。

资源与性能证据需注明提交、场景版本、浏览器、设备、分辨率、画质及实际活动量；未测项留空。现有 `getStats()` 的绘制统计不能代替完整帧 CPU/GPU 测量。
