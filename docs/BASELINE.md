## 动态缺陷过程采集

观察记录在启动与每个采样阶段写入 `observations.json`，包含当前阶段、完成状态及页面提供的版本/浏览器信息。截图、后续操作或资源快照下载失败时保留此前样本，记录失败原因并保持测试失败；进程被强制终止时只能保留最后一次已写入的记录，`running` 不代表成功。录像和部分截图仍须结合实际操作判读。

## 加载、隔离与重置

启动开发服务后，在其地址后加 `?baseline=BASE-02`。此入口只在开发模式启用，使用独立的 `riverlight-baselines` 数据库；正常城市仍使用原数据库。

进入时总是加载固定布局和镜头，不读取正常城市自动存档。测试修改可在隔离数据库保存或导出；重新进入入口会恢复初始布局。「我的城市 → 重新载入基线」会先备份当前测试城市，再重新加载固定入口，恢复初始布局、环境与镜头并清除上次天气的湿润度、云量和动画时钟。正常产品入口不显示基线按钮。

刷新恢复使用 `?baseline=BASE-02&resume=1`：此入口仍使用隔离数据库，读取已保存的测试城市、环境与镜头，刷新时继续恢复。没有隔离存档时使用固定基线；不能用正常城市做故障注入。镜头往返允许小于 `0.000001` 米的浮点误差，城市物件与占地仍须精确一致。

`tests/browser/storage.html` 是开发服务上的独立存档检查页面，每项创建专用测试数据库并清理自身数据，不使用正常城市数据库。自动检查可通过 `npm test` 执行。生成固定文件的入口为 `node scripts/generate-baseline.mjs`。

## 操作与判定

1. 连续两次进入基线入口，比较城市名称、77 个物件、固定时间、画质与镜头；临时车人状态不属于布局等价条件。
2. 选择小屋并移动，按 Esc 取消；原位置和数量保留。移动到水面或重叠位置应拒绝，原城市不变。
3. 拆除小屋后应有 76 个物件；撤销恢复到 77，重做再次为 76，再撤销恢复。
4. 保存为新存档，切换空白城市，再打开该存档；布局、环境和镜头恢复。切换备份可打开或导出原记录。
5. 导出城市后再导入，比较物件 ID、位置、占地、四向角度、道路、水系及环境；无效文件拒绝且保留当前城市。
6. 导入 v1 原件后应使用旧水系与原占地；导入事务保留原始 v1 数据、镜头及输入包装。数据库内原有 v1 记录首次覆盖前也归档原件。迁移、刷新和导出重入仍一致。
7. 启动读取失败时原自动存档不得被示范城覆盖；后续保存进入恢复存档。事务中止时新城市和备份一起回滚，重试可成功。

### T01 米制占地复查

打开独立的 `?scene=T01`，在「观察与记录」导出资源快照。查看 `spatial.samples` 的两个窗口。它们在 X = −64 米相接，都返回同一 ID 的图书馆，占地范围 X = −70 至 −58 米、Z = −16 至 −6 米。右侧窗口还包含 10 × 12 米办公楼及 20 × 16 米商场。快照同时记录陆地 0 米和水面 −0.4 米。该检查沿用现有占地与四向角度，任意角度和地块偏移在后续任务验收。
