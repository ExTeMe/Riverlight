更新：2026-10-16。本文只记录实现与兼容性边界；目标架构见 SYSTEMS，阶段标准见 DEVELOPMENT_PLAN。任务状态与逐次验收证据直接在 GitHub 查询，开发操作见 GIT_WORKFLOW。

当前为集成原型；模型精细度、结构多样性与整体画面均未通过验收。任务和当前阶段以 GitHub 为准。

## 当前实现与正在修改的部分

项目入口是 `index.html` → `src/main.js`，使用 Three.js 与 Vite。旧入口和资源保留在 `legacy/` 及原目录。

现有代码包含基础自由建造、编辑、撤销重做、分区显示、扩展地图、本地保存、JSON 导入导出、昼夜天气、音景与观赏模式。本轮用户要求全面提高模型、城市布局、道路、水岸、夜景与生活感；整体体验仍需按对应任务验收。

## 数据、尺度与兼容性

城市数据独立于 Three.js 显示资源。离开分区只释放显示对象，返回时从城市数据重建。起始范围 128×128 个 4 米逻辑单位；细格为 2 米，界面须区别“逻辑地图范围”和“建筑细格占地”。每次扩区向四边增加 16 个逻辑单位。

存档自版本 3 起单独记录地块和建筑。地块保存稳定 ID、中心 X/Z（米）、局部矩形宽深（米）和朝向（度）。建筑通过 `parcelId` 引用地块，记录沿地块轴的 `offsetX`、`offsetZ`（米）和相对角度 `angle`（度）。可以保存空地块，每块至多一栋主建筑。地块和建筑角度都归一化到 `[0°, 360°)`。增大地块不会拉伸模型。

v1/v2 建筑迁移为兼容地块。读取时从米制中心、角度和可选旧 `lot` 恢复格坐标、占地和模型比例。v1 保留原 `legacy` 水系，v2/v3 保留存档指定的 `terrain`。旧建筑和装饰沿用格网编辑。Blender 模型的原始尺寸依据见 `assets/catalog-reference.json`。

格网道路、桥和小径保留 v4 的 `center: [X,Y,Z]` 及 `grid-v1` 布局。v5 有曲线段时改用 `mixed-v1`，每条曲线道路保存 `alignment.start` 和 `alignment.end`，各为 `[X,Y,Z,方向角]`。坐标用米，0° 指向 +X，90° 指向 +Z。两端相距 6–96 米，高度为 0–8 米，偏离端点连线最多 60°。

工具栏「绘制曲线与坡道」可点选端点或输入坐标，提供直线、左右弯和 S 弯预设。预览显示转弯半径和纵坡，阻止穿水、越界、重叠和不匹配的接缝。画布点选可吸附空闲的曲线端点和格网道路格边。选中现有曲线道路后用「调整线形」修改。编辑、拆除、撤销和重做各更新一次拓扑修订号，失败与无变化的编辑沿用原修订号。

`City.roadNetwork` 生成曲线采样、端点、格网断面、车道边和步行边。`laneGraph` 用成对路段的有向连接口合并车道，提供 `nodes`、`edges` 和修订号。格网路口的 `junction` 派生车行面、铺装、停车线、斑马线和转向。每条 `movement` 含入出口、带切线及沿程距离的米制点列、可通行车型。断头路的出口为 `null`。这些数据随拓扑重建，沿用 v5 存档。T02 和 T03 的探针使用实际车模预览路径。常规原型车辆仍走原有格网路线，正式车辆调度由 R4 接续。

步行图消费路段的人行道、小径和斑马线边。模型的入口锚点通过实例变换进入世界坐标。入口与滨水接线检查车行面、实体占地、可建边界和水域。T05 的「步行连接」用青色表示步行边、金色表示车道边，资源快照列出旋转入口在各连通分量中的可达路面类型。

`City.worldBounds()` 返回米制可建边界，`City.surfaceAt(x,z)` 返回地面或水面高度。`City.queryFootprints(bounds)` 返回米制包围盒相交的候选建筑，跨索引桶按 ID 去重。精确检测再检查候选的旋转矩形或凸多边形，允许贴边，按河岸每 2 米的采样剖面检测入水。建筑在地块局部坐标中检查包含，空地可摆装饰，装饰仍受实际建筑轮廓阻挡。建筑目录可提供相对模型枢轴的米制凸多边形 `outline`，现有资产使用矩形建议占地。旧格对象保留原河岸取样规则。详见 [空间设计](SPATIAL_DESIGN.md)。

点击目录快速建造时，自动生成比建筑建议占地宽、深各多 2 米的地块。也可用「划定地块」点击两个对角，或直接输入中心、宽度和进深。选中空地后从目录添加建筑。位置默认吸附到 0.5 米，可切换到 0.25 米或自由。角度默认吸附到 15°，可关闭后输入任意角度。

「移动整块」修改地块原点、朝向和尺寸，建筑保留相对姿态。独立装饰仍在其原来的世界位置。「调整建筑」只修改局部 X/Z 和相对角度。旧格网建筑继续使用原有移动和四向旋转。预览和提交共用 `City.planParcelEdit`，提交后地块、建筑及索引一起更新并支持撤销重做。选框、模型和已建模的入口锚点复用同一姿态，无入口锚点的资产沿用正面回退点。

保护上限为 8192×8192 逻辑单位、100,000 个物件，不等于满密度可见时的帧率承诺。全部城市数据仍驻留内存，自动存档仍为整城快照；大规模编辑有整批显示/交通重建成本。后续优先做分区增量更新、Worker 存档、按需资产加载和真实设备测试。

保存队列由 `src/save-session.js` 管理，捕获调用时的城市快照与镜头，保存不再重新构造 City 或重建占地索引。启动读取/校验失败时不覆盖原自动存档，改写独立恢复存档；可续用最近有效恢复城市并导出原记录。数据库版本 2 增加摘要 store，不改变城市格式版本；存档列表不读取全部城市正文。

切换城市在同一 IndexedDB 事务中写入当前城市备份和新城市，持久化失败前不替换当前显示。新切换备份保留最近 20 份。旧版本历史备份、v1/v2 原始副本、恢复记录和手动收藏不自动清理。正常入口与开发模式的 BASE-02 基线使用不同数据库。固定文件、镜头与操作判定见 [BASELINE.md](BASELINE.md)。

v1–v4 文件导入通过 SaveSession 的共享入口先校验，再在切换事务中归档原始城市、镜头和输入包装。浏览器内旧记录首次写入 v5 时，同一事务也归档原记录。归档失败时整个事务回滚。开发基线的 `resume=1` 参数续用隔离存档，默认基线入口从固定布局初始化。基线重置在备份成功后重新加载固定入口，同时初始化环境过渡状态与动画时钟。

## 协作管理与验收版本

单人开发已退役多人管理自动执行入口；以下历史模块保留用于迁移参考，不再作为开发门槛： `scripts/github-management.mjs`、`scripts/github-collaboration.mjs`、`scripts/workflow-command.mjs` 和 `scripts/github-settings.mjs`；输入、权限、回执、摘要兼容和失败恢复见 [管理工作流规范](../spec/spec-process-cicd-project-management.md)，操作见 [GIT_WORKFLOW](GIT_WORKFLOW.md)。

CI 由 `scripts/ci-policy.mjs` 按比较版本选择文档、管理或完整应用检查。`check-docs` 检查相对 Markdown 链接目标，不检查外链和锚点；隐私扫描读取已跟踪文件，压缩二进制元数据和凭据仍需人工核对。管理事件过滤复用 `managementEventRelevant`，同时检查编辑前后正文；事件输入只从 JSON 文件读取，不插入 shell 源码。

Vite 输出完整源码 SHA 的 `riverlight-revision` 元数据；开发模式与 dev 预览显示提交缩写，本地未提交状态单独标记。证据仍需固定场景和完整版本。Playwright 在真实 Chromium 中复用共享存档检查，CI 保存报告与截图，不提交本地报告。该回归验证原件保护和事务行为，不能代替城市画面与性能验收。

## 实现限制

车辆调度、目的地行为和统一信号通行权由后续阶段实现。分区加载只管理显示资源，全部城市数据仍驻留内存。模型精细度、动画、夜景和音景的完整体验以对应 GitHub 任务的验收为准。

## 代码入口

资源加载使用 Vite 的 `import.meta.env.BASE_URL`：GLTFLoader 的模型目录随构建基路径变化，根目录本地运行与网站子目录均可用。
