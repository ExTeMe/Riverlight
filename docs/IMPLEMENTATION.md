# 栖城：实现方式与边界

更新：2026-10-16。本文只记录实现与兼容性边界；目标架构见 SYSTEMS，阶段标准见 DEVELOPMENT_PLAN。任务状态与逐次验收证据直接在 GitHub 查询，开发操作见 GIT_WORKFLOW。

当前为集成原型；模型精细度、结构多样性与整体画面均未通过验收。任务和当前阶段以 GitHub 为准。

## 当前实现与正在修改的部分

项目入口是 `index.html` → `src/main.js`，使用 Three.js 与 Vite。旧入口和资源保留在 `legacy/` 及原目录。

现有代码包含基础自由建造、编辑、撤销重做、分区显示、扩展地图、本地保存、JSON 导入导出、昼夜天气、音景与观赏模式。本轮用户要求全面提高模型、城市布局、道路、水岸、夜景与生活感；整体体验仍需按对应任务验收。

## 数据、尺度与兼容性

城市数据独立于 Three.js 显示资源。离开分区只释放显示对象，返回时从城市数据重建。起始范围 128×128 个 4 米逻辑单位；细格为 2 米，界面须区别“逻辑地图范围”和“建筑细格占地”。每次扩区向四边增加 16 个逻辑单位。

存档版本 2 增加 `terrain` 区分 `meander` 和 `legacy`。版本 1 恢复时记录旧建筑 `lot` 尺寸并保留旧水系；完整编辑回归仍待做。坐标支持 0.5 逻辑单位，道路/桥/小径仍要求整数逻辑坐标；旋转依旧为 90 度。Blender 模型的原始尺寸依据保存在 `assets/catalog-reference.json`，不要无意覆盖。目标米制契约、任意角度、曲线道路与桥高格式尚未实施。

保护上限为 8192×8192 逻辑单位、100,000 个物件，不等于满密度可见时的帧率承诺。全部城市数据仍驻留内存，自动存档仍为整城快照；大规模编辑有整批显示/交通重建成本。后续优先做分区增量更新、Worker 存档、按需资产加载和真实设备测试。

保存队列由 `src/save-session.js` 管理，捕获调用时的城市快照与镜头，保存不再重新构造 City 或重建占地索引。启动读取/校验失败时不覆盖原自动存档，改写独立恢复存档；可续用最近有效恢复城市并导出原记录。数据库版本 2 增加摘要 store，不改变城市格式版本；存档列表不读取全部城市正文。

切换城市在同一 IndexedDB 事务中写入当前城市备份和新城市，持久化失败前不替换当前显示。新切换备份保留最近 20 份；旧版本历史备份、v1 原始副本、恢复记录和手动收藏不自动清理。正常入口与开发模式的 BASE-02 基线使用不同数据库；固定文件、镜头与操作判定见 [BASELINE.md](BASELINE.md)。

v1 文件导入通过 SaveSession 的共享解析入口校验，并在切换事务中归档原始城市、镜头和输入包装；归档失败时整个导入回滚。开发基线的 `resume=1` 参数可续用隔离存档检查刷新恢复，默认基线入口继续从固定布局初始化。基线重置在备份成功后重新加载固定入口，使环境过渡状态与动画时钟也重新初始化。

## 协作管理与验收版本

单人开发已退役多人管理自动执行入口；以下历史模块保留用于迁移参考，不再作为开发门槛： `scripts/github-management.mjs`、`scripts/github-collaboration.mjs`、`scripts/workflow-command.mjs` 和 `scripts/github-settings.mjs`；输入、权限、回执、摘要兼容和失败恢复见 [管理工作流规范](../spec/spec-process-cicd-project-management.md)，操作见 [GIT_WORKFLOW](GIT_WORKFLOW.md)。

CI 由 `scripts/ci-policy.mjs` 按比较版本选择文档、管理或完整应用检查。`check-docs` 检查相对 Markdown 链接目标，不检查外链和锚点；隐私扫描读取已跟踪文件，压缩二进制元数据和凭据仍需人工核对。管理事件过滤复用 `managementEventRelevant`，同时检查编辑前后正文；事件输入只从 JSON 文件读取，不插入 shell 源码。

Vite 输出完整源码 SHA 的 `riverlight-revision` 元数据；开发模式与 dev 预览显示提交缩写，本地未提交状态单独标记。证据仍需固定场景和完整版本。Playwright 在真实 Chromium 中复用共享存档检查，CI 保存报告与截图，不提交本地报告。该回归验证原件保护和事务行为，不能代替城市画面与性能验收。

## 实现限制

道路和步行连接仍来自网格推算，尚无车道级拓扑、目的地行为或统一信号通行权。分区加载只管理显示资源，全部城市数据仍驻留内存；活动数量和规模上限不能视为实际设备的帧率保证。模型精细度、动画、夜景和音景的完整体验仍以对应 GitHub 任务的验收为准。

## 代码入口

资源加载使用 Vite 的 `import.meta.env.BASE_URL`：GLTFLoader 的模型目录随构建基路径变化，根目录本地运行与网站子目录均可用。

| 文件 | 职责 |
| --- | --- |
| `src/catalog.js` | 稳定目录 ID、原尺寸与新占地、细格尺度 |
| `src/core.js` | 城市数据、占地/分区索引、历史、路网、新旧水系、版本迁移、示范城 |
| `src/asset-loader.js` | 并发载入 Blender 近远 GLB |
| `src/models.js` | 保留 GLB 材质与入口/遮蔽锚点、静态合批、动态子树、材质季节变化、模板，参见[资产契约](ASSETS.md#art-02-模型契约) |
| `src/architecture.js` | 资产加载失败时的备用造型 |
| `src/roads.js` | 道路、圆弧转角、人行道边缘、斑马线、桥梁几何 |
| `src/world.js` | 分区、地形、模型实例、选择/预览、车辆/船与行人模块协调 |
| `src/walk-network.js` | 从现有道路、路径和水岸推算步行图，连接入口，随机邻边路线原型 |
| `src/pedestrians.js` | 自动人物实例、步行更新、步态、粗略车辆等待与资源释放 |
| `src/environment.js` | 天空、水、光、昼夜、四季、天气、落叶 |
| `src/puddles.js` / `src/ambient-occlusion.js` | 局部积水平面反射 / 环境遮蔽 |
| `src/main.js` | 输入、相机、渲染、编辑协调、保存 |
| `src/ui.js` / `src/style.css` | 中文界面、缩略图、面板和响应式布局 |
| `src/storage.js` / `src/audio.js` | 本地存档 / 合成音景 |
| `src/save-session.js` / `src/baseline.js` | 保存队列与原件保护 / 开发模式固定基线 |
| `scripts/blender/` | Blender 原创模型与导出脚本 |

当前玻璃是标准材质反射，水和积水使用平面反射；流畅档关闭积水反射、环境遮蔽和辉光。积雪以材质渐变表现，没有物理厚度。外圈随机背景树已移除；目录内树木仍可编辑。行人路径目前由步行模块推算，不是目标中的道路统一几何源；人物重建会重置活动。未来功能不能写成已交付，长期阶段标准见 DEVELOPMENT_PLAN，具体任务直接在 GitHub 查询。
