# 栖城：实现方式与边界

更新：2026-10-16。本文只记录实现与兼容性边界；目标架构见 SYSTEMS，阶段标准见 DEVELOPMENT_PLAN。任务状态与逐次验收证据直接在 GitHub 查询，开发操作见 GIT_WORKFLOW。

当前为集成原型；模型精细度、结构多样性与整体画面均未通过验收。任务和当前阶段以 GitHub 为准。

## 当前实现与正在修改的部分

项目入口是 `index.html` → `src/main.js`，使用 Three.js 与 Vite。旧入口和资源保留在 `legacy/` 及原目录。

现有代码包含基础自由建造、编辑、撤销重做、分区显示、扩展地图、本地保存、JSON 导入导出、昼夜天气、音景与观赏模式。本轮用户要求全面提高模型、城市布局、道路、水岸、夜景与生活感；整体体验仍需按对应任务验收。

## 数据、尺度与兼容性

城市活动由 `SimulationClock` 以 30 Hz 推进。每帧累积真实时间，最多接收 250 毫秒以限制卡顿后的追赶。隐藏标签页和切换城市期间停止推进，恢复时不补算离开的时间。「暂停城市活动」冻结车、人、船、场所动画和路口轨迹。镜头与环境继续更新，昼夜播放和流速由环境面板控制。模拟步数与暂停是会话状态，不写入城市文件。行人状态按固定步计算，渲染时按镜头刷新实例。

城市数据独立于 Three.js 显示资源。离开分区只释放显示对象，返回时从城市数据重建。起始范围 128×128 个 4 米逻辑单位；细格为 2 米，界面须区别“逻辑地图范围”和“建筑细格占地”。每次扩区向四边增加 16 个逻辑单位。

存档自版本 3 起单独记录地块和建筑。地块保存稳定 ID、中心 X/Z（米）、局部矩形宽深（米）和朝向（度）。建筑通过 `parcelId` 引用地块，记录沿地块轴的 `offsetX`、`offsetZ`（米）和相对角度 `angle`（度）。可以保存空地块，每块至多一栋主建筑。地块和建筑角度都归一化到 `[0°, 360°)`。增大地块不会拉伸模型。

v1/v2 建筑迁移为兼容地块。读取时从米制中心、角度和可选旧 `lot` 恢复格坐标、占地和模型比例。v1 保留原 `legacy` 水系，v2/v3 保留存档指定的 `terrain`。旧建筑和装饰沿用格网编辑。Blender 模型的原始尺寸依据见 `assets/catalog-reference.json`。

格网道路、桥和小径保留 v4 的 `center: [X,Y,Z]` 及 `grid-v1` 布局。自 v5 起有曲线段时使用 `mixed-v1`，每条曲线道路保存 `alignment.start` 和 `alignment.end`，各为 `[X,Y,Z,方向角]`。v6 高架道路增加 `alignment.elevated: true`。v7 圆弧道路用 `alignment.arc` 保存带符号的转角，Bézier 路段保留原有形状。v8 增加可选 `alignment.deckHeight`，桥面与两端接路高度分别保存，引桥按平面弧长和 12% 纵坡上限派生。旧格式继续可读，包含桥坡的城市拒绝降级导出以免丢失数据。坐标用米，0° 指向 +X，90° 指向 +Z。两端相距 6–512 米，普通坡道高度为 0–8 米，高架端点和桥面为 0–32 米。

桥格存档保留历史 `center[1] = 0.45`。桥底、桥墩和引桥由岸线及路网连接在运行时重算，读档、撤销和重做都走同一套规则。已有桥在缺少引桥时与地面道路齐平，满足条件后自动抬高。

曲线坡道和抬高的格网引道使用随路面升降的薄桥板和分离的支撑，曲线高段的栏杆由扶手和立柱组成。选中曲线路段、格网桥或引道时，沿实际坡面绘制琥珀色边带和端部标记。车道、步道及桥底净空沿用同一路段数据。

自动桥型是由现有城市和桥面几何派生的显示信息。连续桥使用入水至出水范围，格网桥的所有桥格共用一次选型。有效方案的预览沿桥面显示对应护栏、斜撑或拱架，选中面板显示桥型名称。附近街区修改或读档后重新计算。

工具栏「绘制曲线与坡道」可拖出道路或点选两端，默认自动相切顺接，也提供直线、左右圆弧和 S 弯。自由端圆点可直接移动，高度标签可拖动或用方向键微调；一端接路时圆弧滑杆移动自由端并保持切线。吸附按屏幕距离选择，Shift 可临时关闭。普通道路和高架都可连续延伸，默认保持高度。绘制时收起目录和场景面板，精细坐标默认折叠。无效预览保留手柄，具体阻挡物显示橙色轮廓。

绘制或调整线形时可点「添加中间点」，再点道路预览线。编号圆点可拖动或选中，面板分别调整该点前后两段的转向。多段曲线在中间点共用切线并生成同一条道路的车道与步道。v9 用 `alignment.via` 保存中间点，用 `alignment.bends` 保存各段转向。每段端点至少相距 6 米，合计不超过 512 米，最多 16 个中间点。v8 及更早格式继续可读，带中间点的道路需要 v9。

开发场景 T04-WEST 的前场沿用小径记录。临街建议取相邻实际人行道的采样切线。平台和直缓坡作为一个操作提交、拆除或撤销。试验专用的 v10 保存一个 `riverfrontPlatform`，包含稳定 ID、坡底 X/Z、宽深、朝向、坡长、升高和净宽。坡底从小径通行高度派生，台面与坡道共用顶面角点和步行中心线。导入重新校验陆地、岸道、净宽、坡度、占地和底端全宽贴合。普通城市及无平台快照仍写 v9。 [场景复现](BASELINE.md#t04-west-西岸街坡试验)

`?scene=WEST-BUILDINGS` 在开发服务器复用西岸的地块和平台能力，加载独立样板目录和存档。样板的目录高度上界在模型加载前用于桥底净空。步行连接面的绘制略低于端点的实际铺装，步行坐标仍使用原高程。 [住宅与市集实施记录](../rpi/riverlight-building-art/implement/IMPLEMENT.md)

选择工具下 Ctrl + 点击逐个增减物件。批量移动和旋转预览整组轮廓，建筑与所属地块一起移动，旋转围绕组中心。含格网物件的组以 90° 旋转，其他组以 15° 旋转。编辑前使用整组的新位置检查道路、地块和物件碰撞，每次应用或拆除对应一次撤销。

「自动桥坡」保留接路端点并提供独立桥面高度；「整体升降」可调整本段或整条相连道路。共享端点的邻路随高度联动，地面格网接口保持原高。`planRoadAlignment` 构造完整变更集并对最终状态校验，不修改当前城市；`editRoadAlignment` 一次提交邻路更新及显式勾选的小径/街景清理。建筑、道路和码头保留。失败不产生部分更新，撤销重做和读档复用同一路网规则。一次事务仅更新一次拓扑修订号。

`City.roadNetwork` 生成曲线采样、端点、格网断面、车道边和步行边。`laneGraph` 用成对路段的有向连接口合并车道，提供 `nodes`、`edges` 和修订号。格网路口的 `junction` 派生车行面、铺装、停车线、斑马线和转向。每条 `movement` 含入出口、带切线及沿程距离的米制点列、可通行车型。断头路提供按车型校验的停车路径，车道图由此生成对向的出发边。车辆和 T02、T03 的探针使用同一套转向定义。

步行图消费路段的人行道、小径和斑马线边。模型的入口锚点通过实例变换进入世界坐标。入口与滨水接线检查车行面、实体占地、可建边界和水域。T05 的「步行连接」用青色表示步行边、金色表示车道边，资源快照列出旋转入口在各连通分量中的可达路面类型。

`City.worldBounds()` 返回米制可建边界，`City.surfaceAt(x,z)` 返回地面或水面高度。`City.queryFootprints(bounds)` 返回米制包围盒相交的候选建筑，跨索引桶按 ID 去重。精确检测再检查候选的旋转矩形或凸多边形，允许贴边，按河岸每 2 米的采样剖面检测入水。建筑在地块局部坐标中检查包含，空地可摆装饰，装饰仍受实际建筑轮廓阻挡。建筑目录可提供相对模型枢轴的米制凸多边形 `outline`，现有资产使用矩形建议占地。新建、移动和复制按完整占地检查水域。读档允许旧格网规则已接受的河岸位置，保留原位置和格式。详见 [空间设计](SPATIAL_DESIGN.md)。

点击目录快速建造时，自动生成比建筑建议占地宽、深各多 2 米的地块。也可用「划定地块」点击两个对角，或直接输入中心、宽度和进深。选中空地后从目录添加建筑。位置默认吸附到 0.5 米，可切换到 0.25 米或自由。角度默认吸附到 15°，可关闭后输入任意角度。

「移动整块」可在场景里拖动中心手柄平移地块和建筑，或沿地块自身方向拖动一条边。拖边时对边和建筑世界姿态固定，数字面板同步更新宽深和中心。「调整建筑」的手柄只改变建筑局部 X/Z，数字面板也可修改相对角度。独立装饰仍在原位置。预览和确认共用 `City.planParcelEdit`，地块、建筑及索引作为一次编辑支持撤销重做。

移动预览期间，原建筑暂时从分区显示、阴影和拾取中隐藏。取消后恢复原模型，确认后显示新位置。复制预览保留原模型。

保护上限为 8192×8192 逻辑单位、100,000 个物件，不等于满密度可见时的帧率承诺。全部城市数据驻留内存，自动存档按分批序列化的整城快照写入。普通建筑编辑只刷新受影响分区的显示对象，路网变化仍可重建桥面和交通。

保存队列由 `src/save-session.js` 管理，捕获调用时的城市快照与镜头，保存不再重新构造 City 或重建占地索引。启动读取/校验失败时不覆盖原自动存档，改写独立恢复存档；可续用最近有效恢复城市并导出原记录。数据库版本 2 增加摘要 store，不改变城市格式版本；存档列表不读取全部城市正文。

切换城市在同一 IndexedDB 事务中写入当前城市备份和新城市，持久化失败前不替换当前显示。新切换备份保留最近 20 份。旧版本历史备份、v1/v2 原始副本、恢复记录和手动收藏不自动清理。正常入口与开发模式的 BASE-02 基线使用不同数据库。固定文件、镜头与操作判定见 [BASELINE.md](BASELINE.md)。

v1–v8 文件导入通过 SaveSession 的共享入口先校验，再在切换事务中归档原始城市、镜头和输入包装。浏览器内旧记录首次写入 v9 时，同一事务也归档原记录。归档失败时整个事务回滚。开发基线的 `resume=1` 参数续用隔离存档，默认基线入口从固定布局初始化。基线重置在备份成功后重新加载固定入口，同时初始化环境过渡状态与动画时钟。

## 协作管理与验收版本

单人开发已退役多人管理自动执行入口；以下历史模块保留用于迁移参考，不再作为开发门槛： `scripts/github-management.mjs`、`scripts/github-collaboration.mjs`、`scripts/workflow-command.mjs` 和 `scripts/github-settings.mjs`；输入、权限、回执、摘要兼容和失败恢复见 [管理工作流规范](../spec/spec-process-cicd-project-management.md)，操作见 [GIT_WORKFLOW](GIT_WORKFLOW.md)。

CI 由 `scripts/ci-policy.mjs` 按比较版本选择文档、管理或完整应用检查。`check-docs` 检查相对 Markdown 链接目标，不检查外链和锚点；隐私扫描读取已跟踪文件，压缩二进制元数据和凭据仍需人工核对。管理事件过滤复用 `managementEventRelevant`，同时检查编辑前后正文；事件输入只从 JSON 文件读取，不插入 shell 源码。

Vite 输出完整源码 SHA 的 `riverlight-revision` 元数据；开发模式与 dev 预览显示提交缩写，本地未提交状态单独标记。证据仍需固定场景和完整版本。Playwright 在真实 Chromium 中复用共享存档检查，CI 保存报告与截图，不提交本地报告。该回归验证原件保护和事务行为，不能代替城市画面与性能验收。

## 实现限制

路网拓扑改动后重建车辆行程，安全减速与改道由 #37 接续。统一信号通行权和行人目的地行为仍待实现。分区加载只管理显示资源，全部城市数据仍驻留内存。模型精细度、动画、夜景和音景的完整体验以对应 GitHub 任务的验收为准。

当前玻璃是标准材质反射，水和积水使用平面反射；流畅档关闭积水反射、环境遮蔽和辉光。积雪以材质渐变表现，没有物理厚度。外圈随机背景树已移除；目录内树木仍可编辑。路网编辑后步行图会重建，人物活动也会重置。长期阶段标准见 DEVELOPMENT_PLAN，具体任务直接在 GitHub 查询。

西岸建筑样板在 GLB Empty 中保存 `riverlightLightColor`、`riverlightLightDay`、`riverlightLightNight` 和 `riverlightLightRange`。运行时沿用建筑姿态变换、昼夜渐变和邻近 8 个点光预算。材质可用 `riverlightDayGlow` 表示灯罩的昼间自发光，灯位独立照亮附近表面。
