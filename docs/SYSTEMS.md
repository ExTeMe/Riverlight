# 系统需求、边界与接口约定

更新：2026-11-10。本文定义目标设计。实际实现边界见 IMPLEMENTATION，执行状态与验收证据直接在 GitHub Issues/Projects 查询。

## 0. 共同约定

- 运行时空间采用米，Three.js 的 Y 轴向上，地面为 XZ。网格仅作为编辑吸附/空间索引，不能成为所有建筑和道路的几何限制。
- 现有 `CELL=4`、`SNAP=.5` 表示 4 米逻辑单元中的 2 米细格；迁移时要明确单位，不能把 UI 格数、世界坐标和模型尺寸混用。
- 城市长期数据（建筑/道路/桥梁/环境设置）与临时活动状态（车、人、船）分开。只卸载显示区域时不删除城市数据。
- 拟新增统一模拟时钟，固定时间步推进交通、信号和行人；渲染可插值。太阳时间流速与交通模拟速度分别定义，避免调快昼夜后信号和车辆失步。
- 城市编辑产生带版本的拓扑变更。道路、步行、航路消费者检测失效并重新规划，不能持有已删除对象继续移动。
- 建议采用以下数据契约逐步迁移，**尚未全部实现**：`AssetDefinition`、`BuildingInstance`、`RoadSegment`、`Junction`、`LaneGraph`、`WalkGraph`、`Waterway`、`BridgeDefinition`、`EnvironmentState`。

| 契约 | 至少包含的字段/含义 |
| --- | --- |
| AssetDefinition | 稳定 ID、结构变体、米制尺寸、原点、二维占地、入口/停靠/屋檐锚点、材质语义、动画、LOD、资源成本 |
| District / Parcel | 玩家片区的可选边界和分组；地块独立的 ID、米制原点、角度、局部边界 |
| BuildingInstance | ID、地块、资产与变体、地块局部偏移和角度、配色；世界姿态由同一变换派生 |
| RoadSegment | 端点、中心线、宽度、坡度/高度、车道配置、两侧步道、拓扑版本 |
| Junction | 进口/出口、停车线、转向连接、冲突区、过街线、信号相位 |
| LaneGraph / WalkGraph | 可达边、几何曲线/高度、方向、代价、限速/通行条件、所属道路/入口、版本 |
| Waterway / BridgeDefinition | 航路边界、水位、桥面/桥底高度、桥墩障碍、可通航包络、引桥坡度 |
| EnvironmentState | 时间、季节、降雨/降雪强度、风、湿润度、积雪、室外暴露；供材质、角色和音频共同读取 |

## S01 世界与空间

**职责**：坐标、地形、水岸边界、空间查询、分区数据与显示生命周期。不能在渲染模块内部另写一份水岸公式供算法猜测。

玩家片区、可编辑地块、实际占地和加载分区分别建模。首版尺寸、相对姿态和 T01 验收见[空间设计](SPATIAL_DESIGN.md)。

**需求**：细分吸附；矩形/多边形真实占地；宽阶段空间索引、窄阶段 OBB/SAT 碰撞；不同高度层；跨分区查询；世界扩展与确定性重建。

**接口**：提供高度、水面/陆地、可建造区域、占地相交和附近设施查询；被编辑、道路、桥梁和步行系统共用。

**验收**：任意旋转建筑不能穿楼、压河或越界；分区边界不改变查询结果；离开/返回后数据一致。实现前不把整个城市做成统一高精度网格。

## S02 建筑编辑与角度放置

**现状差距**：当前只支持 0/90/180/270 度；不能称为自由角度。

**需求**：放置预览、画地块、移动或旋转整块、单独调整建筑的局部偏移与角度、复制、删除、配色。地块和临街方向可参考道路切线，允许关闭位置和角度吸附。

**规则**：新姿态以度保存。地块和建筑的局部姿态合成后供预览、渲染、碰撞、选择框、入口和遮蔽点读取。调整地块边界保持建筑米制比例。

**兼容性**：旧 `rotation=0..3` 无损映射为 90° 倍数；旧 `lot` 和模型比例保留；失败移动/旋转不改原建筑。

**验收**：T01 覆盖 0°/15°/30°/45°/90°/非吸附角度，检查不同真实尺度、地块内偏移、合法贴边、越界失败、历史和保存一致性。

## S03 道路、人行道与路口几何

**现状差距**：现有网格圆角只改善外观，完整曲线道路编辑、车道级拓扑和道路尺度仍需重做。

**需求**：直线/曲线道路、左右弯和 S 弯，T 字/十字/断头路、桥梁连接；清晰的车道宽度、路缘石、人行道、斑马线及停车线；编辑时显示弯曲半径和不可行反馈。

**规则**：中心线生成路面、车道中心、人行道与路口入口；它们不得由各系统分别猜偏移。弯道切线连续，限制过小半径和车道自交；路口建立进口到出口的转向曲线。车辆尺寸决定车道宽度，不能在不足宽度的道路中硬塞双向公交。

**输出**：带修订号的 LaneGraph/WalkGraph，以及可渲染网格；拆改局部道路使相关路径失效。

**验收**：T02 所有转弯方向、坡道、接缝和跨分区连接无裂缝、翻面；车、人路径位于对应可见表面；曲线附近建筑能按切线或自由角度放置。立交/隧道为后续，不混入首轮。

## S04 水系、桥梁与船舶

**职责**：河道边界、水面高度、滨水步道、码头、通航包络与桥梁结构。船不是沿固定公式循环穿越一切的装饰。

**需求**：有宽窄、弯曲与岸线层次的河流；连续步道、护岸/自然岸、平台和码头；桥面、桥底、桥墩、桥头和引桥明确；航路位于可航水域，船有目标、转向、速度及停靠状态。

**桥下净空**：使用 `桥底最低高度 - 最高适用水位 >= 船舶水上最高点 + 浮动幅度 + 安全余量`。还需船宽/转弯包络与桥墩之间有横向空间。以经过变换后的模型包围盒验证，不能只看名义高度。

**不通航处理**：规划替代航路或在安全位置停止并提示；不可缩小船、穿桥、把船隐藏一帧蒙混过去。建桥时预览净空影响；提高桥面必须同步坡道、车道、步行高度及桥墩。

**验收**：T04 最大船型在水位/浮动极值、不同方向和连续多个桥孔下都不穿桥墩/桥底；桥上的人车无跳高、沉入或断路；航路尽头不在镜头中瞬移。

## S05 车辆算法与行为

**现状差距**：当前随机选择邻接道路，加曲线插值；没有可靠的目的地路线、跟车、停车线或冲突控制。

**需求**：合法入口生成，目的地选择，车道图 A* 路径，沿弧长采样运动；限速、加减速、弯道降速、跟车间距、排队、到达/离场；轿车与公交有不同长宽、转弯半径和速度参数。

**规则**：前车间距限制目标速度，停车线制动距离至少考虑 `v²/(2a)` 和余量；不能直接移动到下一个节点。驶入路口前同时检查信号、冲突区许可和出口空间。先完成单车道跟车/路口，再做变道、公交运营等扩展。

**接口**：只读 LaneGraph，向路口请求通行许可；提供位置、包络、速度和预计占用信息给过街系统。路径失效时减速到安全状态再重规划。

**验收**：固定随机种子的 T03 连续运行中无追尾/对穿、越线抢灯、逆行或不可解释的瞬移；转弯不侵入人行道；不同帧率下结果不依赖渲染帧数。

## S06 红绿灯与路口协调

**职责**：统一管理车辆和行人通行权。红绿灯模型只是状态显示，不能独立于模拟计时闪烁。

**需求**：进口方向、停车线、转向冲突矩阵、绿/黄/全红切换、行人等待和过街清空时间；无信号路口明确让行规则。

**首轮策略**：采用简单可验证的保护相位；行人过街可先用独立全车红灯相位，优先正确性。后续再做更真实的同向行人放行、转弯让行和自适应配时。

**规则**：一处路口一个状态源；禁止冲突方向同时获得许可；已经进入的参与者优先清空，不在路口内因灯变而突然停车；出口堵塞不得继续放入。

**验收**：测试覆盖完整相位周期、黄灯临界、行人尚未离开、出口堵塞及编辑删除路口；灯色和实际放行一致，无无限互相等待。

## S07 行人算法与日常行为

**现状**：已新增步行图、自动路人和行走动画原型；当前路线仍是邻边随机游走，粗略检查附近车辆，不是完整目的地寻路和信号协调。

**需求**：从住宅、交通入口或公共场所自动生成；根据开放入口选择商店、公园、码头等目标；WalkGraph A*；沿连续人行道行走、到达、停留、返回/离场；合理数量和昼夜活动变化。

**状态机**：生成 → 选目标 → 规划 → 行走 → 等待过街 → 过街 → 到达/停留 → 再规划/离场。无路可达时安全停留或在不可见位置退出，不穿楼、水或围栏。

**局部行为**：不同步速、避让、同向间距、窄路队列；步态/摆臂按行进距离驱动，转身平滑；等待时停止走路动作。不需要完整 NavMesh 或真实人口模拟即可先实现可信街道活动。

**雨天行为**：露天且降雨超过阈值时选择撑伞或前往可达屋檐/室内；用迟滞和短过渡避免雨强临界时反复开合；伞跟随手/身体锚点，收伞不突兀，进室内不穿屋顶。晴天不会全员一直拿伞。

**接口**：入口/遮蔽点来自资产元数据；过街许可来自 S06；降雨/暴露来自 S09。道路编辑后重新规划，保留安全当前位置。

**验收**：T05 无手动摆人即有活动；能观察完整“住宅→步行→等灯→过街→商店/公园”过程；雨天撑伞、进入遮蔽收伞和停雨恢复均可重复检查；不得以增加人数掩盖逻辑缺失。

## S08 Blender 资产与多样性

**用户要求**：所有正式建筑、住宅、商业、公共建筑、公园/场所通过 Blender 建模；目前资产类型数不是质量验收结果。

**资产标准**：真实米制尺度，统一 pivot/前方，应用必要变换；干净法线、倒角、结构合理；入口、橱窗、阳台、檐口、屋顶设备和室外空间与用途相符；材质有墙/屋顶/玻璃/窗灯/招牌等语义；近远景轮廓一致。

**多样性**：先为住宅、沿街商铺、公寓、高层制作结构变体；变化至少涉及体量、屋顶、开口或街面布局，颜色仅作附加。图书馆、学校、美术馆、医院、商场、游乐园不能沿用同一塔楼结构。

**首轮样板建议**：6 类代表，各先完成一个精细版本；重点住宅/商业再各做至少 3 个结构变体作为扩充模板。数量是实施目标，最终以视觉和资源验收为准；未达标不批量复制到全城。

**导出契约**：GLB + 可编辑 BLEND + 元数据 + 缩略图 + LOD + 动画；资产 ID 稳定，变体另设 ID。制作完成后在 Three.js 中检查材质、阴影、动画绑定、碰撞轮廓和夜景，不能仅看 Blender 渲染。

**资源预算**：R1 在实际样板上记录三角面、材质数、纹理和 draw call，再确定分级预算。避免为细节增加大量独立 Mesh/材质；利用合批、实例化、材质共享和 LOD。

## S09 昼夜、季节、天气与角色联动

**需求**：独立设置时间/季节/天气、平滑切换、风、雨雪、落叶、湿润度、积雪与融化；统一环境状态供渲染、路人、车辆、船和音景使用。

**行为联动**：下雨不止粒子——行人撑伞/避雨，湿地渐变，水面涟漪，音景变化；夜晚店铺/住户按用途有不同灯光和活动强度。积雪/落叶分布与实际树木/地面对应。

**验收**：重复切换和长时运行无粒子耗尽、状态跳变或帧率依赖；雨停后地面逐渐干燥、人物收伞；天气不能改坏路径和存档。

## S10 场景渲染、画风与城市构图

**方向**：精致卡通微缩、柔和但清楚的光影；繁华街区与优美水岸兼具，避免廉价几何拼贴、发灰/泛黄一片或满屏过曝窗户。

**美术基准**：R1 固定镜头和参考板，定义比例、色板、材质粗糙度、玻璃表现、阴影软硬、植被尺度、灯光亮度与后处理强度；全资产统一，不给每栋楼单独套风格。

**材质方向**：不能过于卡通化；保留木、石、墙面、沥青、玻璃和金属可辨认的质感，细节尺度适合微缩城市。用固定近中远镜头及不同光照的样板确认，导入不得丢失作者定义的纹理、法线、粗糙度和金属度。

**空间构图**：沿街连续店面、不同高度群组、局部留白、公共目的地、连贯水岸和天际线；绿化出于设计目的，外圈不随机堆树。缩略图、全景和近景均可辨认建筑用途。

**夜间层次**：少量室内深度与窗帘明暗、部分开灯、店招/街灯/设施灯分级；发光材质与实际照明区分。水面和湿路反射有不同粗糙度与范围，避免统一镜面。

**验收**：T06 固定相机对比；近景细节、中景城市活动、远景轮廓均成立。确认车人船行为后再截图，不用静态角度藏穿模。性能档有明确效果取舍。

## S11 保存、历史与可靠性

**需求**：自动/手动、多城市、切换备份、导入导出、版本迁移；地块、相对偏移、新角度、道路曲线、桥梁高度、资产变体都有稳定序列化。编辑命令事务化，可撤销/重做。

**规则**：导入先完整校验再替换；迁移不覆盖唯一旧数据；未知版本清楚拒绝。临时车/人重建不能改写用户建筑与道路。

**恢复与隔离**：启动读取失败不覆盖原自动存档，后续修改另存为恢复城市；原记录可导出。切换备份与新城市持久化为同一事务，存储失败保留当前城市。自动清理只处理本版本创建的滚动切换备份，历史备份、旧城原件与手动收藏保留。开发测试入口与正常城市存储隔离。

导入旧格式文件时，原始城市数据、镜头与输入包装须在替换事务中一起归档；不是只保留转换后的快照。固定基线重置还须清除环境过渡状态和运行时钟，刷新恢复则继续使用已保存的城市与镜头。

**验收**：旧版本→新版本→导出→重入；无效/重叠/丢资产输入；中途取消及失败回滚；扩大世界后恢复一致。

## S12 UI、相机与声音

**需求**：类别/变体选择、明确尺寸/角度/放置反馈、道路工具与净空提示；建造/自由观察、近景/全景、隐藏界面、跟随、截图；音量与音乐/环境独立控制。

**规则**：UI 展示真实状态，红绿灯和交通调试信息只在开发检查面板出现；不要向玩家暴露无关实现细节。声音需用户操作后启用，雨声/河声/车声随环境和距离变化。

**声音获取与风格**：素材现阶段由用户搜索和提供；需要时说明具体场景、触发方式、时长、循环/变体及空间表现并向用户询问。声音风格随场景和氛围确定；音频制作软件与 MCP 留待后续决定，不能以统一柔和音色替代各场景的实际听感验收。

**验收**：鼠标、键盘、大屏及较窄窗口下主要动作可达，输入控件不误触镜头快捷键；截图与保存不改场景状态。

**公开说明**：README 让首次访问者理解项目、启动和使用方式，准确标注早期开发状态；不把内部工作记录或未确认讨论作为项目首页，不展示未经验证的线上体验链接或过时截图作为当前画面。

## S13 性能、测试与调试

**需求**：分区增量更新、批量绘制、LOD/活动预算、模拟与渲染分离；道路/入口/车道/步行图/净空包络调试覆盖；固定种子、固定镜头、固定存档。

**性能方法**：记录硬件、浏览器、画质、分辨率、可见建筑/车/人数，再测帧时间、内存与绘制次数；目标值在 R1/R7 基线后确定，不能写虚构的“稳定 60 FPS”。

**目标设备与取舍**：游戏电脑优先，偏重画面质量；T06/T07 以高画质建立主要基线，同时检查建造、镜头及保存响应。具体硬件、分辨率、帧时间及活动预算仍须实测确定；低画质作为可选降档，不以削减主要视觉效果替代高画质验收。

**验收**：高密度、远近切换、雨夜、反复编辑与保存、长时运行无资源持续增长和逻辑失步。模拟单元测试、跨系统集成、浏览器交互、视觉对照各自有证据；不能互相替代。
